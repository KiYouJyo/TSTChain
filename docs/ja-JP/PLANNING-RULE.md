# 計画ルールプロトコル — v0.3

TST Chain v0.3 は、計画要件をバージョン管理可能・機械可読・検証可能なルールとして表現します。

`PlanningRule` は**何を検証するか**を定義し、`RuleEngine` は**特定の入力をどのように評価したか**を示します。チェーンはルール版、入力ダイジェスト、エンジンID、結果を記録しますが、GIS・BIM・TIM や行政裁量を置き換えません。

### 対応するルール表現
- 数値しきい値・範囲
- 列挙条件
- 真偽条件
- 空間述語

十進数は `"2.5"` や `"45"` のような正規化文字列で表し、JSON の二進浮動小数点は使用しません。

### 例外
例外は発行主体、有効期間、根拠を持つ独立オブジェクトです。元ルールを黙示的に変更しません。`review_required` は自動承認・拒否ではなく `review` を返します。

### 外部エンジン
`TST-RULE-ENGINE/0.3` で能力を宣言します。GIS / BIM / TIM 実装はチェーン外で空間・モデル計算を行い、証拠参照付き観測結果を返します。

### 結果の意味
`pass`、`fail`、`review`、`not_applicable`、`error` は機械評価状態です。法的・行政的な決定は別の署名可能な業務イベントとして扱います。
