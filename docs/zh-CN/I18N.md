# TST Chain 三语与本地化规范

TST Chain 正式支持：

- `zh-CN` — 简体中文
- `ja-JP` — 日本語
- `en-US` — English

## 基本原则

### 1. 机器字段永远使用英文稳定 key

协议字段、Schema、代码符号、枚举值、数据库 key、签名 payload 和 Hash 输入不得根据显示语言变化。

正确：

```json
{
  "event_type": "PLAN_APPROVED"
}
```

显示层：

- zh-CN：规划批准
- ja-JP：計画承認
- en-US：Plan approved

禁止把翻译后的字符串写入共识关键字段。

### 2. Locale 文件只保存用户可见文本

目录：

```text
locales/
├─ zh-CN.json
├─ ja-JP.json
└─ en-US.json
```

三个文件必须拥有完全一致的 key 集合。

### 3. 英文术语作为语义锚点

新增核心概念时，应先确定唯一英文机器术语，再确定中日译名。译名变化不得迫使协议字段迁移。

### 4. 核心术语优先固定，不随意同义替换

推荐术语：

| Machine term | 简体中文 | 日本語 |
| --- | --- | --- |
| Territorial Spatial Trust Chain | 国土空间可信链 | 国土空間信頼チェーン |
| Spatial Object | 空间对象 | 空間オブジェクト |
| Spatial Event | 空间事件 | 空間イベント |
| Planning Rule | 规划规则 | 計画ルール |
| Authority | 权责主体 | 権限主体 |
| Provenance | 规划谱系 / 来源谱系 | 来歴 |
| Evidence | 证据 | 証拠 |
| Workflow | 业务流程 | ワークフロー |
| Jurisdiction | 管辖范围 / 事权范围 | 管轄範囲 |
| Checkpoint | 检查点 | チェックポイント |
| Credential | 凭证 | クレデンシャル |

涉及中国特有制度术语时，优先保留准确中文概念，并在日英文本中使用解释性译法，避免强行套用国外制度名词。

## Key 命名规范

使用点分层级：

```text
app.name
app.description
core.spatialObject
core.spatialEvent
core.planningRule
core.authority
core.provenance
status.active
status.superseded
status.revoked
```

要求：

- 使用 `camelCase` 子段；
- 不在 key 中出现语言代码；
- 不使用完整句子作为 key；
- 删除 key 属于兼容性变更，应进入变更记录；
- 新增 key 必须同时补齐三种语言。

## 文档结构

```text
docs/
├─ zh-CN/
├─ ja-JP/
└─ en-US/
```

重要架构文档应尽量保持三个版本标题与章节结构一致。若某语言版本暂未同步，应明确标注更新时间或同步状态。

## 协议与本地化边界

以下内容不得本地化：

- JSON / CBOR / protobuf 字段名
- 枚举常量
- Content hash 输入
- 数字签名 payload
- URI scheme
- Object/Event/Rule ID 格式
- Schema ID 与版本号
- 错误代码

以下内容应本地化：

- UI 标签与说明
- CLI 人类可读提示
- 文档
- 错误信息解释文本
- 示例中的标题、描述和注释

## 测试要求

后续 CI 应至少验证：

1. 三个 locale 文件 key 集合完全一致；
2. JSON 可解析且无重复 key；
3. locale 文本不会参与 canonical hash 测试向量；
4. 核心术语变更经过显式 review；
5. 缺失翻译时测试失败，而不是静默回退进入正式发布。
