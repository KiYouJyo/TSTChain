# TST Chain v0.7 — Distributed Ledger Prototype

v0.7 introduces the first persistent authoritative ledger for TST protocol/workflow outcomes. It is intentionally a planning-governance ledger prototype, not a cryptocurrency network.

## Ledger semantics

- Append-only entries are chained by SHA-256 predecessor hashes.
- Entry payloads use RFC 8785 JCS before SHA-256 so ordered arrays keep their meaning.
- Accepted workflow transitions and rejected attempts are both persisted; rejection never mutates authoritative state.
- Auditable `state_seed` entries can bootstrap externally supplied benchmark/initial state without making the disposable snapshot authoritative.
- `state-snapshot.json` is only a disposable cache. Authoritative workflow state is recovered by replaying the ledger.
- Duplicate request replay is idempotent and does not append another ledger entry.
- Evidence and provenance records are payload-hash bound. The reference ledger can later compare a current evidence/provenance digest against the persisted approved/historical digest and persist the verification result.

## Checkpoint and finality

A checkpoint commits the ledger prefix through a deterministic Merkle root. `quorum_signed` finality requires Ed25519 approvals from an active authority-based validator set. Verification covers both the quorum signatures and a Merkle root recomputed from the actual referenced ledger prefix; a signed checkpoint cannot be detached from different ledger contents.

## Trust-anchored state synchronization

`StateSyncBundle` is the v0.7 reference synchronization envelope. It carries exactly one finalized ledger prefix together with its checkpoint and validator-set description.

Import is intentionally **trust anchored**: the receiving node must supply its locally trusted validator set. A validator set merely included by the remote bundle is not accepted as a trust source. The bundle validator set must exactly match the local trust anchor before checkpoint signatures are considered.

A sync import verifies:

1. outer bundle hash and v0.7 bundle shape;
2. ledger ID, sequence, predecessor chain, payload digests and entry hashes;
3. locally trusted validator-set identity and public keys;
4. checkpoint hash and Ed25519 quorum;
5. checkpoint `through_sequence` / `entry_count` against the supplied prefix;
6. Merkle root recomputed from the actual ledger prefix;
7. compatibility with any existing local prefix.

The reference importer rejects self-authorized remote validator sets, divergent local forks and synchronization attempts that would roll a node back from a longer local ledger. After import, the snapshot is regenerated by normal ledger replay.

This is a **finalized-prefix synchronization prototype**, not a complete peer-to-peer replication protocol. It does not yet implement peer discovery/authentication, streaming or incremental propagation, validator-set evolution, BFT network consensus, or production recovery/operations procedures.

## ReferenceCity benchmark

The v0.7 ReferenceCity adapter consumes only the isolated benchmark-input bundle generated by ReferenceCity with `ground_truth_included=false`. TST Chain writes observed S001–S010 results through the persistent ledger; Ground Truth scoring is then performed separately by ReferenceCity `compare_observed.py`.

For the pinned ReferenceCity commit `f810758d151a36747dbc7ccf11998f12d40bef4e`, Python 3.11 / 3.12 / 3.13 all reach **10/10**, corresponding to **10 full / 0 partial / 0 unsupported** under the repository's synthetic-benchmark definition of `full`.

This does not imply government production admission, statutory effect, operational security accreditation, or real-data deployment readiness.

## Prototype boundary

The local JSONL file is rewritten atomically for prototype safety. Remaining distributed-ledger work includes node identity and peer authentication, checkpoint-chain and validator-set evolution, crash/interrupted-write recovery, incremental state synchronization and actual multi-node replication.

## Non-goals

There is no native tradable token, mining, Gas requirement, DeFi primitive or financial consensus incentive in the v0.7 core.
